# 中文条号切块（HA-0093）

1. 共用切块器在行首识别普通中文数字条号：`第` + `一二三四五六七八九十百千万零〇两`组成的非空串 + `条`。阿拉伯数字、Markdown、原有章/列表边界保持不变；不解析条号数值，也不验证法律编号是否正确。财务大写、繁体條、条号内部空格暂不支持。
2. 短条款分别形成父块和子块；超长条款仍按既有父/子长度上限拆分。平台`clause-N`始终是顺序证据块ID，不等于原文条号，不能承诺一条一块。
3. CRLF/CR规范化为LF后，父/子块的start/end、原文切片、摘要、覆盖必须一致；缩进只影响原文位置，不得重复计算前导空白。
4. 正文中的内联“依照第十二条”不触发新标题；仅凭行首结构判断，不能区分刻意伪造的标题，也不构成提示注入防护。
5. 行为版本记为`heading-policy@2`（由代码提交和本规格标识），JSON形状仍为adaptive-chunk@1，没有新增持久化版本字段。旧Run、产物和收据不重写；新执行的中文文档可能改变块数、ID和页数。尚无证据续跑；不得把旧编号直接继承给新切块结果。
6. 验收包括12条中文和阿拉伯对照、中文数字边界、缩进/换行、长条款限制和零丢字、官方SDK+合成Provider读取最后一块。新评测另存，不覆盖旧结果；共享切块器的原有测试也必须通过。

非目标：语义相关性/注入判定、真实模型准确率、中文法律条号校对、跨Run编号稳定、自动迁移、生产部署。
