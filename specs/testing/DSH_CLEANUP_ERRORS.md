# DSH 清理故障（HA-0092）

- 信号发送、等待退出、关闭管道、停止网关和释放工作目录租约是独立的清理阶段。前一步的 OSError/TimeoutExpired 不得让后续资源释放被跳过。
- 清理时已存在初始化、取消、期限、网关等主异常，保留该主异常，不用清理异常覆盖它；原始清理异常文本不得进入产品事件。
- 正常运行结果遇到清理故障时不得发布成功，返回固定 DSH_CLEANUP_FAILED。不把 PermissionError 当成进程已退出。
- 发信号被拒后不再尝试对该组发送其他终止信号。仍有界等待已拥有的 Popen 子进程，并关闭本进程的管道和租约。
- 工作目录仍只通过既有 journal、flock、进程组、inode 检查删除；组仍活着或权限未知时保留 pending。不得为了清理成功而删除仍被使用的目录。
- 不增加模型调用、重试或权限，不改变恢复流程不杀 PID 的边界。此次不声称解决 PID/PGID 复用或操作系统为何返回 EPERM。
- 验收：各清理阶段故障注入、主异常身份保留、正常结果拒绝发布、后续清理实际执行、活进程目录保留；既有真实子进程启动测试、完整验证和独立复审。
