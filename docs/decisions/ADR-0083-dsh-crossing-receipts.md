# ADR-0083：DSH 过境身份与同进程重放防护

状态：实施中。用户于 2026-10-06 要求继续推进、验证、部署；依据已批准的 07–10 讲报告 B。只交付 B，不混入 A2 证据续跑。部署范围沿用独立本地 DSH 8876，不改 8765/132。

## 契约

1. 平台在每次执行建立随机 generation。身份为 Run + generation + kind(model/tool) + 模型轮次 + 工具序号。模型原始 tool_call_id 只保留摘要关联，不作为去重身份。平台返回给 SDK 的工具 ID 替换为平台签发的票据；SDK execute 使用 exec.callId 送回。模型首票 m_1 在本 Run 的短期认证网关内有效，后续模型票和工具票只能由平台上一轮结果签发。
2. `/model` 和 `/tool` 使用严格 `{crossing_id, request}` 信封。相同身份绑定规范化 JSON 请求摘要；同内容重投只返回首次响应，改参或改工具拒绝；新一轮同原始 ID、同参数仍是新动作。没有全局按参数去重。所有请求仍先检查取消/截止。
3. SQLite 保存 issued / in_flight / completed / failed / unknown 状态、请求/响应摘要、原始 ID 摘要，不保存参数、模型正文、工具正文或 notice。每次状态变更与 metadata-only `dsh.crossing` 事件同事务。实际 Provider payload 的摘要仍在既有业务预算账本中；crossing 的 request_sha256 是网关输入摘要，二者不可混称。
4. 首次响应只在 Run 的有界内存缓存中保留（最多 8 次模型与 32 次实际工具；签发票据另受每轮 16 个上限约束）。回放逐值返回原响应，包含原 notice，不重新运行工具、不修改进展、提交次数或模型/工具计数、不再次扣费；回放本身不写事件。平台调用锁串行化并发重投，取消使用独立 Store 锁可继续执行。
5. 响应缓存不是检查点，不跨进程恢复。重启将未完成 receipt 标为 failed（尚未开始）或 unknown（已进入执行）；原 Run 按现有恢复语义失败，绝不自动重发 Provider。已提交动作但尚未写收据时崩溃也保守 unknown，不宣称 exactly-once。预算 sent→unknown 和冻结规则不变；完成收据缺缓存时拒绝回放。
6. 工具只可使用上一轮模型实际签发、且名称和参数摘要完全匹配的票据；尚有未完成工具时不能推进下一模型轮。旧已完成票据仅能回放，不能重新执行。取消/终态之后连缓存回放也拒绝。
7. 内部回调接口随信封升级；上游 SDK/依赖不修改。公开 Task/Run HTTP 协议不变。新增表为附加迁移，旧 Run 无收据可正常读取。

## 验收

跨轮同名 ID；同票改参；未签发/跨 Run 票据；并发重投；成功回包丢失；提交与 notice 原样回放；重启 unknown；取消后重投；动作计数和预算不增加；数据库/事件零正文。官方 DSH SDK + 合成 Provider、业务定向回归、完整 verify、部署 release/PID 绑定、浏览器及小额公开/合成真实模型证据分别记录。

不宣称外部 exactly-once、跨进程续跑、OS 沙箱、语义正确性或生产多租户。
