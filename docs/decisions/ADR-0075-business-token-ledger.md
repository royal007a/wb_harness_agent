# ADR-0075：业务模型调用的持久共享 Token 账本

日期：2026-10-04
状态：离线组件已实现、作者验证通过，待独立复审；真实业务 Runtime 准入不变。

## 原子范围

落实 ADR-0074 的第一步：可供平台传输桥使用的 SQLite 预算账本及单次调用包装器。
不替换 Pi Loop，不改 Claude 路由，不提供新的公开 HTTP 或网络客户端；不部署未接入的组件。
生产 Service 不构造这个账本，因此不会修改正式 DB。实例测试只使用临时 Store。

## 契约

- 平台注册根 Run、固定模型绑定摘要及 1..20,000,000 的累计 Token 上限。根 ID 不可重建、重置或改上限。
- 子 Run 由平台显式绑定到已登记父节点，并共用同一根账本；成员 ID 唯一，不得迁移到另一根。
- `reserve` 在 Store 的 BEGIN IMMEDIATE 内同时检查根状态、调用 ID、余额并记录请求摘要、成员、purpose 和输入/输出额度。purpose 为 primary/child/retry/compaction/guard；调用 ID 在根内只能用一次。
- `spent + reserved <= limit` 才能继续预留。输入上界由平台可信计数函数计算，不能接受模型传来的数量；本阶段不提供或声称已验证豆包 tokenizer。
- `mark_sent` 在真正发送前再次检查根状态。凭证解析/取消发生在发送前时可释放；发送后超时、取消、异常或缺用量保留整笔预留并冻结根，禁止重试及后续子调用。
- 正常 usage 必须是非负整数（不接受 bool）、输入/输出/total 对账一致，且输入不超预留输入、输出不超输出上限。结算恰好一次；不把缓存 Token、推理 Token 再与 Provider total 重复相加。
- Provider 报告超出预留时记录实际 total、冻结根并报 breach；账本不能阻止 Provider 不遵守其输入/输出合同，不能据此声称全球计费硬上限已经成立。
- 取消根后不再发送新的请求；已在途的成功响应仍记账，但不能作为成功结果发布。远端停止计费不由本组件保证。
- 进程重启后，只能由持有执行租约的平台在无在途调用时显式 `recover`：释放未发送预留，已发送无结果的预留保留并冻结。构造第二个对象不会自动恢复/释放第一对象的在途余额。
- 包装器不自动重试、压缩或执行工具。返回值是候选模型结果，不是 Product Run 成功；Handoff/Gate 仍由平台完成。

## 无密边界与错误

账本只存 ID、purpose、SHA-256、整数用量与固定状态，不存 Prompt、原文、回复或凭证。
凭证由传输回调在 `mark_sent` 之后自行在边界解析；若无法证明尚未发送，保守视为未知用量。
输入估算失败发生在预留和传输之前。调用包装器捕获 BaseException 以保留取消审计后重抛；异常正文不持久化。
每次调用有显式 0..3600 秒超时（不含零）；超时/取消后最多等待 0.1 秒清理回调。
不响应取消的回调可能仍在后台运行，但迟到结果不会结算或发布，根账本保持冻结；
这不等于远端请求被终止。实际 transport 必须另外证明关闭连接和退出资源的行为。
单次 usage 中任一计数大于 4000 万视为无效且冻结，避免异常数字造成 SQLite SUM 溢出。
本组件限制单次等待；根任务总时长、turn 数及工具上限仍由后续 Product Run 集成强制执行。

## 实际接入前门槛

真实 HTTP/SDK transport、Keychain、可靠输入上界与输出上限证明、货币费用准入、Product Run 绑定和执行租约、Pi sidecar 桥接、部署仍待实现/验收。
本组件接受的平台回调属于可信代码，不是认证或针对任意 Python 调用者的沙箱。不能把任意用户提供的回调或 usage 当可信。
