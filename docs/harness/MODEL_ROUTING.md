# 模型与模态路由

## 原则

- 路由由控制面显式解析并写入 Run，适配器不得自行换模型。
- 模型使用逻辑别名与部署 ID 分离；配置保存模型能力探针和版本摘要。
- 每种模态分别声明输入理解与内容生成能力，不能用“支持图片”一项混合表达。
- 数据分类、地域、预算和上下文上限优先于成本与速度。

## 当前用户指定策略

| 模态 | 路由 | 状态 |
|---|---|---|
| 文本推理/代码生成 | 尚未选择 | Proposed |
| 图片理解、OCR、图表解读 | `doubao-seed-2.1-turbo` | User-selected，需能力探针 |
| 图片生成/编辑 | 尚未选择独立图像模型 | Unresolved |
| 向量化 | 尚未选择 | Unresolved |

这里把“图片类”解释为图片输入理解，因为公开产品信息将 Seed 系列与 Seedream 图像生成系列分开。若目标实际是生成或编辑图片，必须选择并验证独立图像生成端点，不默认由 `doubao-seed-2.1-turbo` 承担。

## 能力探针

在任何真实调用前，记录以下结果：

- 账户内实际 endpoint/deployment ID；
- 图片输入是否可用，支持的 MIME、大小、分辨率和数量；
- OCR、表格、图表和多图对比的固定样例结果；
- 工具调用、结构化输出、流式响应和取消支持；
- Token 计量、费用、延迟、地域和数据保留规则；
- 失败码、限流和内容安全返回。

探针失败时返回 `MODEL_CAPABILITY_MISMATCH`，不得静默回退到其他模型。

## P0.1 图片扩展路径

P0 基线只接收 CSV，图表由沙箱代码生成，不调用图片模型，其 Task 的 `model_policy.vision` 为 `null`。HA-0005 探针通过后，可在 P0.1 接收截图、扫描表格或解释生成后的图表；此时创建 `vision_analysis` Step，并把 `model_policy.vision` 显式固定为 `doubao-seed-2.1-turbo`。

图片进入模型前必须完成格式检查、恶意载荷扫描、尺寸限制、元数据清理和数据分类；模型输出只能作为分析信号，关键数字仍需由确定性代码从源数据回算。

## 官方信息说明

[火山引擎豆包大模型产品页](https://www.volcengine.com/product/doubao)列出了 `Doubao-Seed-2.1-Turbo`，但当前可访问页面没有充分给出该型号图片输入的完整接口约束；公开资料把图像生成列为独立产品能力。因此本策略尊重用户指定，同时把图片能力设为“探针通过后启用”。
