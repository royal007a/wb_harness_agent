# 模型化意图路由：离线评测与影子门禁（准备阶段）

状态：**准备中，不启用模型路由。** 本文定义在 `rules@1` 之外评估候选模型的最小安全门禁；当前线上预检仍只有 [本地意图契约与规则路由](INTENT_ROUTING.md)。

## 目标与不做什么

目标是让候选模型在进入任何用户可见路由前，先以版本化、脱敏的固定语料输出受限预测，并接受一致评分。该过程只判断意图、两个槽位和是否应拒识；不创建 Product Task、Run 或外部调用。

本阶段不做以下事情：

- 不配置或调用任何模型端点，不读取真实聊天、SQLite Task、上传文件或网盘内容；
- 不把模型分数当作授权，也不改变 `rules@1`、引擎、权限、预算或工作台行为；
- 不允许候选模型自动提交任务、静默跨引擎路由或处理生产敏感数据。

## 三份机器契约

`specs/v1/intent-evaluation.schema.json` 的 `$defs` 定义三类有效载荷：

| 载荷 | 文件/来源 | 必须约束 |
|---|---|---|
| 评测夹具 | `fixtures/intent-evaluation-v2.json` | 手写、`synthetic_deidentified`、无生产用户内容/个人数据/密钥 |
| 影子候选输出 | 由获准运行器另行生成 | 仅 case ID 和结构化预测；不含输入原文、Prompt、凭证或工具结果 |
| 准入策略 | `fixtures/intent-evaluation-policy-v1.json` | 固定最低指标、四类覆盖和仅 `shadow` 执行模式 |

候选输出用 fixture 的 SHA-256 绑定，必须逐例且仅逐例覆盖所有 case ID。它还必须声明 `synthetic_deidentified` 输入分类、Prompt 模板摘要、零工具调用和至少一次模型调用；这些字段是无密审计元数据，不允许出现 Prompt 正文。评测报告同样只记录 case ID、预测和评分，不回显测试目标原文。

## 评分与门禁

评分器是 `harness/evaluate_intents.py`。对每例计算决策、intent ID、缺槽集合和是否路由的精确匹配；整体报告决策/意图/缺槽/路由准确率，以及拒识 precision/recall。它同时校验样例类别覆盖：`supported`、`clarification`、`out_of_scope`、`security_boundary`。

政策阈值是候选进入**下一阶段影子回放**的必要条件，而不是上线许可：

- fixture 至少 24 条，且四类样例都达到版本化最小覆盖；
- 六项指标达到策略下限；拒识 precision 和 recall 都必须为 1；
- 候选声明必须是 `model_shadow` / `shadow`，并且 fixture 摘要严格匹配；
- 所有结构验证、重复/缺失 case 检查和无原文输出检查都通过。

`rules@1` 是本地窄域基线，不被此策略“认证”为模型候选。它可以用扩展夹具做诊断，以暴露语义覆盖与外部副作用表达的缺口；诊断失败不会改变当前 P0 规则的行为。

## 未来影子回放顺序

1. 人工批准提供方、模型 ID、凭证**引用**、预算、地域与允许发送的数据范围；密钥正文不进入仓库、聊天或 Evidence。
2. 在独立获准运行器中仅使用本夹具；运行器生成无输入原文的 `intent-shadow-candidate@1` 结果。
3. 运行评分和策略校验；未通过即拒绝候选，不接入 API。
4. 单独批准后才可对经过脱敏的真实请求做影子比较；影子结果不影响预检响应、不创建 Task，并以聚合指标而非用户正文留存。
5. 另立 ADR、离线基线、故障注入和回滚演练后，才讨论用户可见的模型辅助。即使届时也必须保留确定性权限/资源门禁与显式提交。

## 回滚与审计

当前没有模型开关或运行时集成，因此回滚就是不导入候选输出、维持 `rules@1`。未来每次模型试验必须写入模型/Prompt/fixture/策略版本的无密引用；若任一指标、漂移、泄漏检查或审批失效，立即停止影子运行并撤回候选版本。不得用历史聊天补齐失败样例，也不得覆盖既有评测 Evidence。
