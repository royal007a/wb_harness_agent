# 阅读与改造计划

## 当前判断

仓库没有实现代码，因此现在不存在可供“改造”的调用链。三份参考 PDF 已形成研究记录，当前第一阶段是以受控 CodeAct 数据分析收窄 P0，并验证契约、Smolagents、远程沙箱和视觉模型能力。

## 阅读阶段

### R0：规格对齐

- 核对目标用户、P0 场景、非目标和成功指标。
- 核对任务状态机、API、权限模型与完成定义。
- 将争议项转成 ADR，不在实现中隐式决定。

### R1：官方资料核验

对每个候选引擎单独建立研究记录，至少检查：

- 官方仓库和文档、当前维护状态、版本与发布节奏；
- 许可证、商用限制、传递依赖和供应链风险；
- 语言与运行时要求、部署方式、并发与取消能力；
- 工具调用、流式事件、上下文、检查点和人工批准能力；
- 遥测、Token/费用统计、错误类型和测试支持；
- 已知安全边界以及是否可在隔离环境运行。

不依据二手文章锁定 API，不把名称相似视为协议兼容。

当前进度：Smolagents 的 CodeAgent、ToolCallingAgent、managed agents、MCP 和执行器安全边界已对照官方文档；精确版本、许可清单、取消/检查点行为及远程沙箱仍需可复现探针。`doubao-seed-2.1-turbo` 已按用户要求作为图片理解候选，须用账户内实际 endpoint 验证。

### R2：验证性原型

- 为候选引擎各写最小、可丢弃的探针，不进入主分支核心模块。
- 用相同测试夹具验证能力声明和失败语义。
- 保存版本、命令、事件样本、限制和未解决问题。
- 以评估矩阵决定首个真实适配器，不要求四者同时接入。

### R3：代码形成后的阅读顺序

1. 入口和公共契约；
2. 任务状态机、队列与检查点；
3. 权限、工具运行时和秘密引用；
4. 适配器协议与首个实现；
5. 事件、追踪、产物和评测；
6. 部署、迁移、回滚和故障处置。

每次阅读都产出“事实、推断、未知、风险”四类记录，避免把推断写成现状。

## 改造/实现阶段

### C0：契约冻结

- 定稿 Task、Run、Event、Tool、Approval、Artifact、Adapter Schema。
- 定义状态迁移、幂等、取消、超时、预算和错误分类。
- 建立契约测试夹具与模拟适配器行为表。

### C1：核心控制面

- 实现任务持久化、Outbox、租约、状态机和 SSE。
- 实现项目、Agent 规格、引擎能力和版本管理。
- 不接真实模型，先验证故障和恢复语义。

### C2：安全工具闭环

- 实现只读工具、Schema 校验、策略判断、审计和超时。
- 实现等待批准与一次性授权令牌。
- 完成提示注入、越权和参数篡改测试。

### C3：首个真实适配器

- 以 Smolagents CodeAgent 作为首个候选，用 P0 CSV 夹具核验后再接受选型 ADR。
- 适配器只映射协议，通过统一契约测试。
- 实现取消、错误、用量、事件、产物与 trace 映射。

### C4：评测与运营

- 固定基线数据集、评分器、环境和随机性设置。
- 加入回归门禁、成本与延迟报告、仪表盘和告警。
- 演练依赖中断、积压、回滚和恢复。

### C5：扩展适配器

- 只有在真实需求证明收益时才新增第二个适配器。
- 不为“能力齐全”而强行引入所有候选框架。
- 发现公共契约缺口时先写 ADR，再扩展；不加入私有泄漏字段。

## 每阶段退出物

每个阶段必须交付：评审结论、版本化规格、风险清单、测试或研究 Evidence、未解决问题、下阶段准入条件。未满足退出物不得把任务标为完成。
