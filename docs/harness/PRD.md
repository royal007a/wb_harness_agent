# 产品需求文档

## 背景

长任务容易因上下文膨胀、会话中断、重复扫描和隐式副作用而失控。多个 Agent 引擎又具有不同的调用方式、状态模型和工具协议，使应用难以替换、观测和治理。

HarnessAgent 不追求让模型本身更聪明，而是让项目知识可复用、任务状态可恢复、执行边界可约束、结果可自动验证。

## P0 用户故事

作为分析人员，我可以提交一个已登记 CSV 和分析问题，让 Agent 在受控环境内生成报告与图表；我能看到进度、取消任务、检查代码与计算证据，并确认结果没有访问未授权数据或网络。

详细输入、输出、非目标和验收见 [P0_DATA_ANALYSIS.md](P0_DATA_ANALYSIS.md)。

## P0 最小能力

1. **不可变 Task + Run**：Task 保存意图，Run 保存一次执行状态；两者不混用。
2. **两个适配器**：Mock 用于契约测试；Smolagents CodeAgent 为首个 Proposed 真实适配器。
3. **资源与产物**：登记 CSV，只读挂载输入，受控发布报告、图表和分析清单。
4. **代码沙箱**：模型生成代码只在远程隔离环境执行，默认禁网且限制资源。
5. **三个平台工具**：资源检查、产物发布、最终答案；不为普通统计函数建工具。
6. **事件与可观测性**：记录 Run、模型、代码、工具、产物、成本、trace 和退出原因。
7. **基础评测**：Schema、关键数值回算、恶意输入、产物完整性、取消与超时。
8. **模态路由**：图片理解按用户指定路由到 `doubao-seed-2.1-turbo`，仅在能力探针通过后启用。

## 后续能力

- 只读联网检索 Child Run 和多 Agent；
- 其他真实引擎适配器；
- 知识索引、检索与来源治理；
- 多环境发布、配额、计费和组织级策略；
- 控制台、调试器和评测面板。

## 生命周期

Task 是不可变用户意图，不保存执行状态；Run 是一次执行尝试并拥有状态机。Run 终态不可覆盖，重新执行创建新 Run。完整定义见 [CORE_CONTRACTS.md](CORE_CONTRACTS.md)。

## 关键验收

- 同一 Task 可在模拟适配器中端到端完成并返回稳定结构。
- 服务重启后 Run 可从最近检查点恢复或明确失败，不丢失状态。
- 未授权副作用不会执行，并可通过审批事件恢复。
- 取消信号在规定时间内传递到适配器与工具。
- 每次模型/工具调用均能由 `task_id` 关联到输入摘要、耗时、结果和费用。
- 任何成功 Run 都有结果、终态事件和验证证据。

## 成功指标

| 指标 | P0 目标 |
|---|---|
| Run 状态丢失率 | 0 |
| 未授权副作用 | 0 |
| 取消信号 P95 生效时间 | ≤ 5 秒 |
| 任务事件可关联率 | 100% |
| 回归评测可复现率 | ≥ 95% |
| 固定 P0 样例的关键数值回算一致率 | 100% |

指标口径和采样环境须在实现计划中固定；上述目标不是已实现声明。

## 发布退出条件

- 安全威胁模型完成；
- 状态机和幂等测试通过；
- 故障注入、取消、超时、审批和恢复路径通过；
- 数据保留、导出、删除和密钥轮换流程可验证；
- 运维手册与回滚演练完成。
