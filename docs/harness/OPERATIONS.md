# 运维规范

## 环境

- `local`：开发者隔离环境，可使用模拟依赖。
- `test`：自动契约、集成、评测和故障注入。
- `staging`：与生产拓扑等价，使用隔离数据和凭证。
- `production`：变更受发布门禁、审批和审计约束。

环境配置通过版本化声明管理；密钥只保存引用。禁止用手工控制台变更替代配置记录。

## 发布

1. 固定代码、配置、协议、迁移和适配器版本。
2. 运行对应质量门禁并生成 Evidence。
3. 先发布向后兼容的数据与协议变化。
4. 在小流量环境验证任务、事件、工具和追踪完整性。
5. 逐步放量，持续观察错误率、延迟、队列、费用和评测指标。
6. 记录发布人、审批、版本、时间、健康结果和回滚点。

### 双环境部署要求

除非用户明确限定为“仅本地”或“不部署”，每次需要部署的实现变更必须先发布/验证本机 `http://127.0.0.1:8765`，再发布/验证既有公网 `118.196.123.132` 的 systemd/nginx 拓扑。远端发布前必须创建可恢复的数据库备份；发布后必须验证 loopback health、带认证的 `/harness/` 代理与本次新增接口。Evidence 同时记录两端版本、时间、健康结果与仍关闭的高风险门禁。不得把任何访问密码、token 或本机 Keychain/SQLite 数据复制到远端或写入发布日志。

远端代码先同步到独立 staging 目录并做远端 Python 预检。promotion 时不能对 `/opt/harnessagent` 执行未带 live-target 排除项的 `rsync --delete`：必须显式保留远端的 `.venv/` 和服务数据目录；“复制到 staging 时排除了 `.venv`”并不会自动保护 live target。若发生运行环境缺失，立即记录影响，依据版本化依赖恢复环境和 service health，再继续发布；不得借此跳过本次验收。

## 回滚

- 应用与配置必须支持回退到上一个已验证版本。
- 数据迁移优先使用 expand/migrate/contract，避免要求瞬时回滚 Schema。
- 适配器失败时停止新路由并排空或安全取消现有任务。
- 回滚不得覆盖任务历史；以新事件记录回滚和影响范围。

## 监控与 SLO

至少监控：

- 请求成功率、P50/P95/P99 延迟和限流；
- queued/running/waiting_approval 数量与队列年龄；
- 状态迁移失败、租约冲突、重复事件和恢复失败；
- 模型/工具可用性、超时、错误分类、Token 与费用；
- 沙箱创建/销毁失败、资源越限、残留实例、禁网违规和取消延迟；
- 视觉模型能力不匹配、OCR/图表固定样例回归与确定性回算差异；
- 未授权动作拒绝数、批准等待时间和策略异常；
- 引用完整率、结构化输出通过率和评测回归。

SLO 与告警阈值须基于容量测试和业务影响另行批准，不能在无数据时虚构。

## 故障处置

1. 判断影响范围和数据风险，必要时停止新任务或禁用单一适配器。
2. 保存 trace、事件、状态版本和依赖健康信息，避免污染现场。
3. 优先恢复安全与一致性，再恢复吞吐。
4. 对卡住任务选择恢复、重试、取消或人工处置，并记录依据。
5. 发布用户可理解的状态更新；不得暴露敏感内部信息。
6. 事后记录时间线、根因、检测缺口、修复项、负责人和截止时间。

## 备份与恢复

- 关系数据、对象元数据、策略和审计记录按独立策略备份。
- 缓存与索引应可由事实存储重建。
- 定期验证点恢复和整库恢复，并记录实际 RPO/RTO。
- 恢复演练必须检查任务状态、事件顺序、产物引用和隔离边界。

## 容量与成本

- 按模型、引擎、工具和工作空间记录用量。
- 队列采用背压、公平调度、并发上限和熔断。
- 预算耗尽必须产生稳定退出原因，不能继续隐性消费。
- 扩容策略基于队列年龄和服务时间，不只看 CPU。

## 本地 Runtime 的远程镜像部署

ADR-0022 的远程镜像使用 systemd 绑定 `127.0.0.1:8765`，再由 nginx 在受认证的 `/harness/` 路径代理；模板见 [`deploy/harnessagent.service`](../../deploy/harnessagent.service) 与 [`deploy/nginx-harnessagent.conf`](../../deploy/nginx-harnessagent.conf)。必须保留 `HARNESS_AGENT_RUNTIME=disabled`，除非有单独的数据外发授权和 L3 证据。部署检查至少包含：`systemctl is-active harnessagent`、本机 `/api/v1/health`、代理路径 `/harness/agent-runtime`、SSE 响应头、Basic Auth 拒绝未认证请求，以及 nginx 配置测试。远程镜像不得复用本机 SQLite 文件或 Keychain 凭证。

Ubuntu 的 nginx Basic Auth 文件应为 `root:www-data`、`0640`，以便 worker 读取散列但普通用户不能读取。访问口令只通过受控交接渠道提供，不能写进 systemd 环境、nginx 配置、仓库或 Evidence。

Ubuntu 24.04 的当前镜像源可安装 `uvicorn==0.44.0`，因此 `requirements.txt` 固定该版本；更新依赖前应在本地与目标 Python 版本重新跑完整验证，不能把开发机中不可复现的版本直接当作部署锁。
