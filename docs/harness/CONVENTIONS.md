# 开发与协作约定

## 命名

- 代码、API 字段、事件类型使用英文；文档可使用中文。
- 目录和文件名使用 `kebab-case`，语言生态要求除外。
- 类型使用 `PascalCase`，函数与变量使用对应语言惯例。
- ID 前缀稳定且可辨识，如 `task_`、`run_`、`evt_`、`art_`。
- `HA-xxxx` 仅表示研发治理 Work Item；`task_...` 与 `run_...` 仅表示未来产品运行时对象。
- 事件名至少两段：简单生命周期用 `<entity>.<past-tense>`，例如 `run.started`；子动作使用 `<domain>.<entity>.<past-tense>`，例如 `tool.call.completed`。
- 布尔字段以 `is_`、`has_`、`can_`、`should_` 开头。

## 目录边界

- 公共协议放 `packages/contracts`，不得依赖具体 SDK。
- 核心状态和策略放控制面；引擎差异放 `adapters/`。
- 工具实现与工具授权分离，禁止在工具内部自行决定权限。
- 应用入口只做协议转换，不承载领域规则。
- 测试结构尽量镜像被测模块。

## API 与事件

- 所有写操作定义幂等语义；重试不得重复产生副作用。
- 请求、响应和事件必须有机器可验证 Schema。
- 枚举未知值采取显式失败或兼容分支，不静默映射。
- 错误返回稳定代码、可重试标志和请求 ID，不暴露内部堆栈。
- 事件只追加；修正用新事件表达，不改写历史。
- 破坏性 API 变更通过版本升级和迁移窗口发布。

## 状态与数据

- 数据库状态为事实，缓存和搜索索引均可重建。
- 时间统一存 UTC，展示层转换时区。
- 状态迁移由单一服务拥有并验证预期版本。
- Task 保存不可变意图，不保存执行状态；每次执行或重跑创建独立 Run，Run 终态不可覆盖。
- 外部对象保存内容摘要、来源、分类、保留策略和访问范围。
- 数据迁移必须向前兼容、可观测，并提供独立回滚方案。

## 日志与追踪

- 使用结构化日志；至少包含 `trace_id`、`workspace_id`、`project_id`、`task_id`、`run_id`。
- 不记录凭证、完整敏感正文、思维过程或未脱敏工具返回。
- 模型和工具调用记录版本、耗时、用量、结果分类和错误码。
- 指标标签禁止使用高基数字段或用户输入原文。

## 变更流程

1. 从 `tasks.json` 领取一个 ready 的 Harness Work Item。
2. 高风险或跨模块变更先写 ADR 与 active plan。
3. 先更新协议和测试，再实现最小纵向切片。
4. 按变更范围运行验证矩阵，保存 Evidence。
5. 更新任务终态、计划目录、进度摘要和技术债。

## 提交与评审

- 一个提交表达一个可解释意图，不混入无关格式化。
- 评审描述包含范围、非目标、风险、验证、兼容性和回滚。
- 不把路线图或模拟行为描述为生产能力。
- 临时豁免必须有负责人、到期时间和清理任务。
