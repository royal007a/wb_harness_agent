# 产品范围

## 一句话目标

HarnessAgent 为 Agent 应用提供统一、可审计、可恢复的工程控制面：同一套任务契约可选择不同执行引擎，同时由平台统一管理状态、权限、工具、产物、追踪和评测。

## P0 主要用户

需要分析本地表格数据的分析人员：通过自然语言提出问题，得到可复现的报告、图表和计算证据。

Agent 应用开发者、平台工程师和安全运营人员是 P0 的建设与治理角色，不是首个产品场景的并列主要用户。

## 核心用户流程

1. 登记一个 CSV 资源并描述分析目标。
2. 提交不可变 Task，明确输入版本、引擎、模型、预算和只读权限。
3. 控制面创建 Run；适配器让 CodeAgent 在隔离沙箱中生成并执行分析代码。
4. 沙箱只读输入、只写受控输出，持续返回代码、执行和产物事件。
5. 确定性检查器回算关键指标并检查报告、图表和引用。
6. 用户获得报告、图表、分析清单、成本和 trace，可取消或创建新 Run。

## 路线图参考场景

这些场景用于验证平台能力，不定义平台边界，也不要求一次全部实现：

| 场景 | 主要能力 | 可考察的候选适配器 |
|---|---|---|
| **P0：敏捷数据洞察** | CodeAct、沙箱计算、图表产物 | Smolagents（Proposed） |
| 长篇研究报告 | Skills、资料引用、分阶段写作 | Claude Agent SDK |
| 复杂业务编排 | 子任务、人工批准、全链路追踪 | Claude Agent SDK |
| 动态知识工程 | 检索、文件工作区、增量更新 | DeepAgents |
| 文档审查助手 | TypeScript 工具链、结构化审查 | Pi 系列框架 |

除 P0 外的场景不进入首版范围。候选适配器只在完成官方能力、许可、维护状态和安全边界评估后立项。

## 产品边界

平台负责：

- 统一任务和事件契约；
- 引擎能力登记与显式路由；
- 可恢复任务状态、审批、预算和取消；
- 技能、工具、MCP、资源与产物管理；
- 凭证引用、权限控制、审计与隔离；
- 追踪、评测、回放和运营接口。

平台不负责：

- 训练基础模型或提供通用模型托管；
- 重写候选 Agent 框架的内部运行时；
- 构建一个自动组合所有框架的“超级 Agent”；
- 在用户不知情时跨引擎迁移任务；
- 承载某个具体行业的核心业务事实；
- 允许模型绕过策略直接产生外部副作用。

## 首个里程碑

P0 只交付 [受控 CodeAct 数据分析](P0_DATA_ANALYSIS.md) 纵向链路：CSV 资源、统一 Task/Run、模拟适配器、Proposed 的 Smolagents CodeAgent 适配器、隔离代码沙箱、三个平台工具、事件/产物、取消/超时与基础评测。联网搜索、多 Agent、任意 MCP 和外部写入不属于 P0。
