## 一、每讲要点与排雷方法

**06-05 窗口越大越忽略指令（李号双）**
- 上下文是内存不是硬盘：中间段的约束"在"却"看不见"。
- 按 L0 宪法 8%（永不压缩）、L1 状态 15%、L2 检索 35%、L3 历史 42% 分配预算。
- 头部放宪法、尾部放约束提醒，夹住中间。
- L1 状态每轮从外部存储读出来、替换旧内容，不靠模型记住。
- L3 五级压缩，只从最老的 L3 下手；超过约 2000 字的工具结果写盘，只留路径。
- 排雷：压满上下文后，检查首尾两段是否原样还在。

**08-07 记忆要敢遗忘**
- 记忆除了写入、召回，还要有第三个动作：遗忘。
- 召回时按"时间衰减 + 访问频率 + 最近访问"现算激活值，低于阈值跳过。
- 写入时只拿最相似的 Top-K 旧记忆查冲突，新胜则旧的标 `superseded`，旧胜则新的丢弃。
- 排雷：构造一新一旧两条矛盾记忆，确认旧的那条不会被召回。

**10-07 上下文分诊（黄佳）**
- P0 永远加载，P1 按需原文，P2 压成"结论 + 证据 + 索引"，P3 只挂句柄。
- 错误堆栈强制保留，超预算也要进。
- 每次决策记一条结构化记录：选中/压缩/延后/丢弃 + 原因。
- 盯三个指标：P0/P1 被丢的次数、丢弃数的 p95/p99、P3 句柄回取率。
- 排雷：P0 一旦被丢，直接当系统 bug 处理。

**11-08 语义压缩**
- 三层：先遮蔽工具输出（保留动作），再并入锚点，最后才是极限摘要。
- 锚点五项：意图、已做改动、已做决策、已排除方案、下一步。
- 错误、数字、路径、行号不能被摘要吞掉。
- 极限压缩是该交接或开新会话的信号。
- 排雷：每次压缩记录 `error_traces_preserved`，丢一个错误就告警。

**11-09 信息散落（徐昊）**
- 过时的文档比没有文档更危险，Agent 会自信地执行错误信息。
- 用 SOURCE.md 登记每份知识的来源和更新时机，再配同步 Skill 或会话开始时的提醒。
- 排雷：把每份重复存放的知识都当成一条依赖来管理。

**12-09 渐进发现**
- 广扫 → 聚焦 → 深挖，最后加验证。
- 工具要拆成原子的（grep/读取分开），不要合成一个大搜索函数。
- 每轮设循环上限和 token 预算。
- 每一步留发现记录（阶段、查询、候选数、选中数）。
- 盯 `zero_signal_rate`（跑完一轮一条有效信号都没有的比例）。
- 排雷：先缩小搜索范围再广扫，深挖不超过 2 跳。

## 三、优化排序

**最该做的 3 项**
1. 失败证据不被存根（P0）。
2. 状态消息加"已排除"槽位（P1）。
3. 上下文窗口两处取值加一致性测试，再补逐项分诊记录（P1）。

**不建议做的 2 项**
1. 不要为 DSH 引入跨 Run 的向量记忆或遗忘机制。单个 Run 内平台计划和提交历史已经够用，加了反而会把旧状态和新状态混在一起。
2. 不要加"LLM 摘要式"压缩。它要多一次模型调用，会动到业务 token 账本，还可能抹平引文和数值，破坏"引文必须逐字来自读过的块"这道校验。继续保持"遮蔽 + 超预算拒绝发送"。
