2. **课程里的核心机制，项目大多已经做了**，表里都附了 file:line：
   - 超过窗口 70% 就把旧工具结果替换成摘录，并提示可以回读；仍然放不下就直接报错拒发。
   - 严格检查工具调用和结果的配对。
   - 平台状态与文档内容分开标注可信度。
   - 数值必须出现在逐字引文中，发布的文本由平台生成，不用模型的原话。
   - 每个动作的事件和计划进度在同一事务里写入。
3. **另外 4 项建议**：
   - 合同里"除第 N 条另有约定外"这类引用所指向的条款，用确定性规则并入必读候选（P1）。
   - findings 记录补上文档 sha256、切块参数、引文在原文中的偏移和章节标题，审计时能追回原文位置（P1）。
   - 把字符估算和真实 prompt_tokens 的比值记录下来，只观测、不自动调阈值（P1）。

   - 对单份合同上向量检索：眼下的真问题是切块边界，不是召回率。
   - 按剩余窗口分档的动态编排，以及跨 Run 自动注入的记忆或失败经验：讲这套方案的作者自己承认实践中性价比不高；跨 Run 记忆有投毒风险，还可能把合同正文写进长期存储。
