## 6 讲对照 HarnessAgent DSH：检索、chunk、交接、并发、扇出聚合

运行时只用了 `build_parent_child_chunks`（`dsh_runtime.py:18,202-203`）。`weighted_rrf`、`aggregate_parent_scores`、`expand_parent_context` 和 `retrieval_control` 运行时都没调用，只在测试里用到。下面的结论按这个前提给出。

### (1) 各讲要点与排雷方法

**18 讲 检索机制**
- 要点：缺什么查什么，按"判断→所需证据→已知/未知→值不值得查"四步走；查询空间会随新的观察动态扩缩；只有一个来源能给的信息，用规则绑定到对应 Action，别让模型去猜；索引说明（Index Profile）多了就先检索索引；查询改写要保留硬约束、统一术语、不擅自补事实；HyDE 生成的假想答案只用来定位，不能当证据；用 5W1H 把问题拆成子问题，并映射到数据源。
- 排雷：每条子查询都写清"缺口 → 数据源"，没有对应缺口的查询不发。

**19 讲 Chunk 粒度**
- 要点：先找业务里的最小完整知识单元，再用测试集比较候选大小；切分顺序是结构定大边界、语义定内部边界、长度兜底；表格每行带上表头，长列表每段重复标题；父子文档是"小块负责找、大块负责读"，父块要去重；父块排序用子块的 RRF 聚合（取前 3 个）；需要时按"先小后大"逐级扩展。
- 排雷：改切块参数前，先确认评测标签不依赖块编号。

**20 讲 召回准确率**
- 要点：多路召回统一结构后，先做硬过滤再排序；去重并合并相邻块；用 RRF 融合；指标看 Recall@K、MRR、证据覆盖率、重复率、长尾失败；迭代检索用结构化的 sufficient / missing_evidence 驱动下一轮，并设停止条件（连续两轮无新证据、预算耗尽）；每轮记录查询、来源和新增证据。
- 排雷：先测召回，再测答案，这样才能分清错在召回还是生成。

**09 讲 Agent 间信息传递**
- 要点：每次跨 Agent 交互都是一次"过境"；下行任务包由代码按白名单组装，底线约束作为字段显式携带；上行依次过身份查重、字段裁剪、契约校验、安全门、审计；拒收时只返回短消息并留档；契约只验形状，不判内容。
- 排雷：没在契约里申报的字段一律剥掉，推理过程里的结论不认。

**10 讲 并发**
- 要点：首选隔离（worktree / 状态合并）；读-改-写要做成原子操作（`UPDATE ... WHERE`）；乐观锁的重试范围里不能包含 LLM 调用，冲突时直接失败，交给调度层重派；锁要带 TTL，续约绑在事件循环上；遇到 RESOURCE_BUSY 时按 hint 让步。
- 排雷：选型按"无锁 → 隔离 → 抢占 → 乐观锁 → 悲观锁"从轻到重逐个问。

**33 讲 扇出聚合**
- 要点：聚合按五步走：盘点缺席、归一口径、去重时区分"同源"和"独立"、先给冲突分类再决定是否投票、检查跨分片的接缝；`accepted`（材料齐全）和 `verdict`（结论）要分开；独立证据率最容易被高估。
- 排雷：只有"同一命题、同一对象、同一口径、来源独立"四项都成立时才允许投票。

### (3) 优化建议与不建议做的事

**最值得做的 3 项**
1. 先把评测标签从块编号改成原文锚点，再加检索命中指标。这一项是后续调切块大小、改检索的前提。
2. 搜索结果回传标题路径，例外候选按父块语境判定，直接针对漏掉单独成块的例外条款这一类问题。
3. 让 search_document 支持多词同义 OR 匹配，并返回命中的词。

**建议不做的 2 项**
1. 不为单份合同引入向量库、HyDE、Index Registry 或多层并行召回。HyDE 的假想文本会污染"引文必须逐字来自已读块"这条校验。
2. 现在单 worker 串行，不要把未接线的 `weighted_rrf` 直接接进运行时，也不要在框架里做通用锁管理器或多 Agent 扇出投票。这样做没有收益，投票还会把有条件的例外压平成一个结论。

`HEADING` 正则不识别"第一条"这类中文数字的问题，另一个 agent 正在修，这里没有重复列出。
