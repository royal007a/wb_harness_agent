## 2. 按专题对照

### 2.1 安全护栏 + Hooks
- **已做**：
  - 所有工具都经由同一网关；`controlled.patch.yml` 禁用了列出的 shell、终端、默认 Provider 等插件。这是**插件层禁用，不是操作系统级的网络隔离**。
  - 每个 Run 签发能力令牌，子进程只拿到环境变量白名单。
  - 失败即拒绝（fail-closed）；结果未知时不重试。
  - 事件只记元数据。
- **缺口与处理**：
  - 凭据规则不一致，`agent_runtime` 漏了 password，实测会放行 → **HA-0093 已修**。
  - 截取式引用能把注入文本伪装成干净证据，实测发布了 0 天 → **HA-0096 只做提示**：来源块命中现有规则时追加缺口并要求人工复核。0 天仍会发布，规则之外的写法不会命中，这**不等于防住了注入**。
  - free 模板没有任何输出检查 → **HA-0098** 影子扫描。
  - 工具参数 schema 在插件和 Python 两边各写一份，只比对了工具名 → 待做（P1）：加一个两边契约一致的测试。
- **不做**：
  - HITL 审批流：现在没有不可逆的外部动作。
  - LLM 注入判别器：判别器自身也会被注入。
  - 通用 GuardRule 管道：会扩大绕过面。

### 2.2 可观测性 + 测试质量
- **已做**：
  - 预算账本先预留、未知用量冻结。
  - 合成 Provider 剧本，加上突变测试。
  - 评审绑定版本。
  - 真实模型 E2E 不进 CI。
- **缺口与处理**：
  - 没有单次调用耗时 → **HA-0097**。
  - 付款评测没进 verify，也没有 dataset_sha256，无法比基线 → 待做（P0）。中文条号切块修复后（codex 进行中）需要重新生成基线，届时一起做。
  - 没有只读 Trace 投影 → P1。
  - 没有 prompt/validator 版本戳 → P1。
- **不做**：
  - 把正文、`output_preview` 写进 Trace。
  - 从真实 Run 录制卡带。
  - 自动降级或模型路由。
  - 搭建金额账本或全套监控栈。

### 2.3 上下文工程
- **已做**：
  - 每轮由平台状态重新组装，可信状态放在尾部。
  - 旧工具结果替换为可回读的存根，最新一轮受保护。
  - 超预算拒绝发送。
  - 严格检查调用与结果的配对。
- **缺口与处理**：
  - 驳回反馈也会被存根，而且用 read_clause 取不回来 → **HA-0094**。
  - 中文数字条号（第一条）切不开：实测 12 条只切出 1 块 → codex 正在修（独立切片）。
  - `CONTEXT_WINDOW` 在 Python 和 mjs 里各写一份 → P1：加一致性测试。
  - 状态里没有“已排除的查询” → P2。
- **不做**：
  - LLM 摘要式压缩：多一次调用，还会破坏逐字校验。
  - 跨 Run 记忆或遗忘机制。

### 2.4 工具
- **已做**：
  - 只允许本轮候选工具。
  - 分页返回。
  - 幂等：调用票据。
  - 超时不重试。
- **缺口**：
  - 可纠正的输入错误（编造的 clause-999、查询为空）会直接让整个 Run 失败，模型没有拿到错误提示的机会 → P1，下一批做。越权类错误仍保持直接失败。
  - search 只做了 casefold，没有去空白、没有全角半角归一（NFKC）→ P1。
- **不做**：
  - 工具分层懒加载或工具检索：现在只有 3 个工具。
  - 并行执行或自动重试：会破坏 HA-0083 的串行裁决。

### 2.5 工作流 / Plan / Replan
- **已做**：
  - 计划由平台持有，按事实投影。
  - 动作和计划同事务写入。
  - 防振荡：重复动作和无进展判定。
  - 计划依赖链短（S1→S3→S4）。这只是声明图，不等于实际执行链长度。
- **缺口与处理**：
  - 失败点归因错位 → **HA-0095**。
  - 主体与数值绑定没校验：实测“甲方30日支付、乙方60日开票”可以被写成“乙方应在30日内支付” → P1，下一批做。
  - A2 证据续跑 → P1，仍按 07–10 讲文档的边界执行。
- **不做**：
  - 模型生成计划图（DAG）或合并 Replan 补丁。
  - 计划评估模型。

### 2.6 检索与多 Agent
- **已做**：
  - 迭代停止条件与检索记录。
  - 契约字段白名单。
  - 同身份同内容才回放。
  - 原子抢占。
- **缺口**：
  - 评测标签钉死在块编号上（`exception_clause: clause-5`），切块参数一变标签就失效 → P0。和中文条号修复绑在一起：标签改为原文锚点。
  - 搜索结果不带标题路径；例外候选要求例外词和付款词在同一子块 → P1。
  - 例外缺口用了 `elif`，导致少报一类 → P2。
- **不做**：
  - 对单份合同上向量库或 HyDE：假想文本会污染逐字引文校验。
  - 多 Agent 扇出投票：会把有条件的例外压成一个结论。

### 2.7 架构
- **已做**：
  - 前馈与反馈并存。
  - 计算型校验。
  - 环境可复现。
  - 停止条件。
  - 外部结果不确定时记 unknown、不重做。不承诺“副作用只发生一次”：DSH_CROSSINGS.md 明确，业务动作与完成收据之间不是跨 Provider 的原子事务，网络调用没有 exactly-once。
- **缺口**：语义极性没校验：引文里有“不得”，结论却没有否定，平台不会发现（`dsh_findings.py` 自己也注明了）→ P1，需要先写误判样本集再定规则，避免误伤。
- **不做**：同一个模型再做一遍自评或反思（课程实验：自评 96 分，加严提示词后 88 分，盲区不变）。
